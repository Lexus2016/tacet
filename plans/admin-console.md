# Адмінка користувачів / User admin console

## Мета

Власник бачить усіх користувачів, їхнє використання й стан, і може вручну змінити тариф, дати безлімітний доступ, зафіксувати оплату, заблокувати або розблокувати акаунт.

## Що вже є

- Адмінка шлюзу: вхід за ключем адміністратора, доступ лише з IP оператора, керування маршрутами моделей. Розділу користувачів немає.
- Дані в базі шлюзу: акаунти (пошта), пристрої, тариф акаунта, використання за місяць і день, щоденна статистика запитів за платформою й моделлю.
- Користувач із поштовим акаунтом сам тариф змінити не може; для нього існують лише тарифи free, basic і pro. Безлімітного доступу, блокування й обліку оплат для таких акаунтів немає.
- Дата реєстрації й остання активність акаунта не зберігаються.

## План

1. Розширити дані акаунта: дата створення, остання активність, стан (активний або заблокований із причиною), тариф із позначкою джерела (безплатний, оплата, вручну адміністратором) і датою, до якої він діє. Додати безлімітний тариф, доступний лише через адмінку.
2. Журнал дій адміністратора: хто, коли, що змінив і чому. Кожна ручна зміна тарифу, оплата й блокування лишає запис; записи не редагуються.
3. Облік оплат: сума, валюта, дата, спосіб, зовнішній номер платежу, примітка. Спершу ручне внесення; коли з’явиться платіжний сервіс і покупки Apple, ті самі записи створюватимуться автоматично. [Оплата на Mac](macos-subscriptions.md) · [Оплата на iPhone](ios-subscriptions.md)
4. Список користувачів: пошук за поштою, фільтри за тарифом і станом, сортування за використанням та активністю. У рядку — тариф, використання аудіо й тексту за період, кількість пристроїв, остання активність.
5. Картка користувача: використання по днях і платформах, пристрої з можливістю відкликати, історія оплат і дій. Дії: змінити тариф, дати або зняти безлімітний доступ із терміном, внести оплату, заблокувати чи розблокувати, видалити акаунт на запит користувача.
6. Блокування діє одразу: шлюз відхиляє запити заблокованого акаунта зі зрозумілим поясненням у застосунку, а вхід за поштою для нього не видає нових ключів.
7. Зведення для власника: кількість акаунтів за тарифами, нові за період, сумарне використання й оціночна вартість провайдерів, щоб бачити собівартість безплатного тарифу.
8. Перевірити на копії бази: зміна тарифу й блокування набувають чинності з наступного запиту, журнал повний, дії недоступні без сесії адміністратора.

## Безпека

Адмінка лишається закритою за IP і ключем. Перед тим як у ній з’являться персональні дані й оплати: окремі облікові записи адміністраторів замість одного спільного ключа, другий фактор, підтвердження руйнівних дій. Пошта користувачів не потрапляє в журнали сервера.

## Відкриті питання

- Чи потрібні кілька адміністраторів із різними правами, чи адмінка лише для власника.
- Термін зберігання використання й оплат і порядок видалення даних на запит користувача.
- Єдина таблиця тарифів: у шлюзі зараз дві з різними цінами; адмінка має працювати з однією.

## English

An owner console on top of the existing gateway admin: a searchable user list with plan, usage, devices and last activity; a user page with daily usage, device revocation, payment and action history; actions to change plan, grant time-limited unlimited access, record a payment, block or unblock, and delete an account. Needs new account data (created, last active, status, plan source and expiry), an admin-only unlimited plan, an append-only audit log and a payments table that manual entries and, later, the payment provider and Apple purchases both write to. Blocking must take effect on the next request. Before personal data and payments appear there: per-admin accounts, a second factor and confirmation for destructive actions.
